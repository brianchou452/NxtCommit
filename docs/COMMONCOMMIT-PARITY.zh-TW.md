# commoncommit 畫面與流程移植對照

[English](COMMONCOMMIT-PARITY.md)

使用者明確指定以 commoncommit 為畫面基準。現在 NxtCommit 直接使用 `src/commoncommit` 的原版畫面，串接既有 API、SQLite、帳本、執行器及部署。這是加入 NxtCommit 的功能，不是另外部署一份網站。

## 比較範圍

來源為 commoncommit `a52346519fa7258a56ec39f70212b243d599e833`；目標基準為 NxtCommit `0d4d8a81f34ed8bebca47892655a91662919b900`（0.7.33）。機械盤點見 `commoncommit-parity-inventory.json`：10 個來源頁面模組、19 個元件模組、35 個具名 CSS 動畫定義。35 是移入的定義數量，不代表 35 個完全獨立的缺漏功能。同時進行但尚未提交的來源修改不列入這次可重現基準。

Agent Lab 與 GitHub 工作區仍可從整合導覽進入。既有 NxtCommit 元件及舊版 golden 保留於專案作為歷史參考；移植路由以這次選定的來源畫面為準。

## 資料與執行界線

轉接層只轉換 API 格式，不建立第二套後端或帳本。市集舊歷史清楚標為唯讀來源示範，不會因此取得執行權限。匯入的 repo 仍沒有可執行工作區；只有明確綁定的內附 fixture 可執行。新增的 tempo 保留來源測試及兩次修正腳本：基準 13 項；第一次 18 項通過、2 項失敗；修正後 20 項通過、0 項失敗。要求修改後的重跑會加入來源 feedback 回歸測試。

規劃和動畫是示範；測試結果來自真正執行的程序。未知量測顯示破折號，不補造數字。核准會記錄本機審查；本機 Release 只接受已核准、成功執行的示範 fixture 及引擎產物，記錄 `upstreamPublished: false`，重試不重複建立。這不會發布 GitHub Release 或套件。

受保護的共用 Demo 啟動時不清除既有資料。提供者流程使用既有建立 API 準備新的 tempo 任務。贊助重試沿用同一意圖識別，具名事件串流同步更新個人頁與錢包。

## 設計與驗證證據

來源頁面、元件及視覺規格保留於 `docs/reference/commoncommit`，屬於參考文件，並非新增註冊的契約，也不表示其中來源測試路徑可在此執行。整合契約為 `spec/components/commoncommit-presentation.yaml`。已檢視原版 golden，未覆寫既有核准圖片。預期差異包含 NxtCommit 品牌、Agent Lab／GitHub 導覽、既有 10,000 點示範錢包、目前市集與帳本，以及明示的歷史證據界線。

前端在 strict 模式下採來源的索引／選用欄位設定；`tsconfig.check.json` 保留後端、共用契約及測試較嚴格的設定。既有後端回歸測試持續執行；來源畫面流程取代舊 UI 專用選擇器，舊瀏覽器測試保留為明確的 legacy 專案。現行驗收亦包含原有 GitHub 工作區與 Agent Lab 流程。瀏覽器截圖作為檢視證據，不宣稱像素完全相同，也不自動核准新版 golden。

回滾使用本次發布提交的反向修改。資料異動為增量，部署前資料庫另行私下備份；不會自動還原而覆蓋更新的使用者活動。
