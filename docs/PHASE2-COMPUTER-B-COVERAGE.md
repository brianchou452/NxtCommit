## Scope and integration dependencies

B owns mission lifecycle, funding, execution, queue and their APIs/components/pages. Follow `skills/yaml-spec-to-code/references/three-computer-phases.md`, not the older product roadmap's unrelated Phase 2.

A owns design-system, home-demo-seed, global i18n, root React router, migration registry, central BDD entrypoint, Playwright config and reset orchestration. B supplies locale fragments and integration requirements without implementing A's slice. C owns project explanation/model-assistance and consumes the shared reviewability/evidence contracts; B supplies ExecutionEvidenceReader.

Mission detail explanation (C) and comment wall (A) are cross-owner dependencies: B verifies partial failure, retry and stale-response isolation, but this inventory does not assign A/C endpoint implementation to B. Public metadata is never executable; only copied bundled fixtures may execute.

Each page scenario additionally requires a Docker Playwright UI journey against the real build. Server BDD, TODO entries and screenshot-only checks are insufficient. Test paths below are declared or planned, not evidence that files exist or tests passed.
